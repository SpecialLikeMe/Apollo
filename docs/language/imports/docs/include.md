# Include

## What it is

`include` brings the source of another file into the current compilation unit at parse time. Unlike `extern`, which imports a module's exported symbols into a separate namespace, `include` inlines the included file's source as if it were typed in place.

This is the C-style include — useful for shared declarations, project-wide constants, or generated headers.

## When you use it

- Sharing constant declarations across multiple files.
- Pulling in machine-generated headers (build-time generators).
- Composing a single compilation unit from multiple source pieces.

For ordinary code organization, prefer `extern` modules. Include is for situations where namespace-based composition is impractical.

## Syntax

```
includeStmt : 'include' STRING ';' ;
```

The string is a path resolved relative to the current file's directory (or to the project root if it starts with `/`).

## Semantics

`include "path/to/file.apollo";` reads the file's contents and parses them in place. Any declarations in the included file become part of the current file's top-level scope.

Includes are processed before the rest of the file is parsed. Cyclic includes are rejected.

Unlike C's preprocessor, Apollo's `include` is grammar-level — it cannot conditionally include or define macros. For build-time conditional inclusion, use the build driver's configuration.

## Examples

### Shared constants

```apollo
// constants.apollo
const i32 MAX_USERS = 1024;
const i32 BUFFER_SIZE = 4096;
const str APP_NAME = "apollo";

// main.apollo
include "constants.apollo";

int main() {
    sys.printf("%s with up to %d users\n", APP_NAME, MAX_USERS);
    return 0;
}
```

The constants file is inlined; the constants are available as if declared in `main.apollo`.

### Shared type declarations

```apollo
// types.apollo
struct Point { i32 x; i32 y; };
struct Rect { Point topLeft; Point bottomRight; };

// main.apollo
include "types.apollo";

int main() {
    nconst Rect r = Rect(Point(0, 0), Point(100, 100));
    sys.printf("%d,%d -> %d,%d\n",
        r.topLeft.x, r.topLeft.y,
        r.bottomRight.x, r.bottomRight.y);
    return 0;
}
```

Types declared in the include become available everywhere in the including file.

### Generated header

```apollo
// build/version.apollo (generated by build script)
const str VERSION = "1.2.3";
const i32 BUILD_NUMBER = 4567;

// main.apollo
include "build/version.apollo";

int main() {
    sys.printf("%s build %d\n", VERSION, BUILD_NUMBER);
    return 0;
}
```

Build scripts can generate Apollo source files that are then included into the program.

### Multiple includes

```apollo
include "constants.apollo";
include "types.apollo";
include "helpers.apollo";

int main() {
    // all three files' contents are available
    return 0;
}
```

Order matters only if later includes reference earlier ones.

### Include with project-root path

```apollo
include "/shared/common.apollo";

int main() {
    sys.println("included from project root");
    return 0;
}
```

A leading `/` resolves against the project root rather than the current file's directory.

### Include inside a multi-file build

```apollo
// platform/linux/syscalls.apollo
const i64 SYS_WRITE = 1;
const i64 SYS_EXIT = 60;

// main.apollo
nativemode;
include "platform/linux/syscalls.apollo";

int main() {
    syscall(SYS_WRITE, 1, "ok\n", 3);
    syscall(SYS_EXIT, 0);
    return 0;
}
```

Platform-specific constants pulled in via include.

## Common mistakes

- **Including the same file multiple times.** Each include re-injects the file's source; multiple includes produce duplicate declarations and rejection.
- **Cyclic includes.** Always rejected.
- **Using include where extern would work.** Includes inflate compile time and pollute the namespace; prefer modules for normal code sharing.
- **Path confusion.** Relative paths resolve against the current file's directory; absolute paths against the project root. Be explicit.
- **Including across language boundaries.** Apollo's include is for Apollo files only — it cannot include C headers. For C code, use inline foreign blocks.
