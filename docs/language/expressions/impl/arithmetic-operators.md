# Arithmetic operators — implementation

## Grammar surface

```antlr
additive       : multiplicative (('+' | '-') multiplicative)* ;
multiplicative : unary (('*' | '/' | '%') unary)* ;
unary          : ('-' | '+') unary | postfix ;
```

Left-associative; `*`/`/`/`%` bind tighter than `+`/`-`.

## Frontend validation

`Apollo-Main/compiler/cpp/src/apollo_runtime.cpp`:

1. Resolves both operand types; rejects mismatched types.
2. Confirms the operator applies to the operand type (integer or float).
3. Sets the result type to the operand type.

## Lowering

In `Apollo-Main/compiler/cpp/src/visitor.cpp`:

| Op | Signed int | Unsigned int | Float |
|----|------------|--------------|-------|
| +  | add        | add          | fadd  |
| -  | sub        | sub          | fsub  |
| *  | mul        | mul          | fmul  |
| /  | sdiv       | udiv         | fdiv  |
| %  | srem       | urem         | (rejected; use math.fmod) |
| unary - | sub from 0 | sub from 0 | fneg |

## Runtime support

None for plain arithmetic. The `core` module's checked variants insert overflow tests using LLVM intrinsics (`llvm.sadd.with.overflow`, etc.).

## Edges and gotchas

- LLVM IR is signedness-agnostic, but the chosen instruction depends on the source-level type.
- Division by zero is undefined at the LLVM level. Checked builds may wrap with a runtime fault.
- Float `%` is not generated by the arithmetic surface; the frontend rejects it for floats.
